AI-POWERED TECH EVENTS AGGREGATOR PROJECT CHECKLIST
======================================================

PROJECT OBJECTIVE
-----------------
Goal: Build an AI-powered Tech Events Aggregator that collects and unifies all technology-related events in New York City (initially for October 2025) from multiple sources like Eventbrite, Meetup, Luma, and Partiful.
The system should use APIs + scraping + AI filtering to output a consolidated, searchable dataset or web dashboard.

------------------------------------------------------
PHASE 0 — SETUP & PLANNING
------------------------------------------------------
Objective: Create the project environment and structure before writing code.

Tasks:
1. Create a GitHub repository (e.g., nyc-tech-events-aggregator)
2. Initialize Python virtual environment (python -m venv venv)
3. Install base dependencies:
   pip install requests beautifulsoup4 playwright pandas sqlalchemy psycopg2 openai
4. Create folder structure:
   src/
     ingestion/
     processing/
     storage/
     api/
     frontend/
   data/
   logs/
   notebooks/
5. Set up .env for API keys (Eventbrite, Meetup, OpenAI, etc.)
6. Write a README.md describing the goal, architecture, and dependencies.
7. Add .gitignore (include venv/, .env, __pycache__, /data)

------------------------------------------------------
PHASE 1 — REQUIREMENTS & SCOPE DEFINITION
------------------------------------------------------
Objective: Clearly define what data you need and from where.

Tasks:
1. Define city (New York City), month (October 2025), and topic (Technology, AI, Startups, Software).
2. Create table of target platforms: Eventbrite (API), Meetup (API), Luma (Scraper), Partiful (Scraper)
3. Define standard event fields (id, title, description, start_time, end_time, city, venue, tags, category, url, source)
4. Document expected outputs (CSV, JSON API, optional frontend view)

------------------------------------------------------
PHASE 2 — DATA INGESTION LAYER
------------------------------------------------------
Objective: Collect raw event data via APIs and scrapers.

A. Eventbrite API
- Register for Eventbrite Developer Account
- Create API key, test /events/search endpoint
- Save JSON response → data/eventbrite_raw.json

B. Meetup API
- Register for Meetup Developer key
- Test /find/upcoming_events endpoint
- Save JSON response → data/meetup_raw.json

C. Luma & Partiful (No API)
- Create Apify account
- Use “Luma Scraper” and “Partiful Scraper” actors
- Run for NYC, keyword “Tech”
- Retrieve JSON via Apify API → /data/luma_raw.json, /data/partiful_raw.json
- (Optional) Use Playwright to scrape custom pages

D. Store all raw data
- Create folder data/raw/
- Log timestamps and API success/failure in /logs/ingestion.log

------------------------------------------------------
PHASE 3 — DATA PROCESSING & NORMALIZATION
------------------------------------------------------
Objective: Clean, combine, and standardize event data.

Tasks:
1. Create script: src/processing/normalize_events.py
2. Load raw JSONs → Pandas DataFrames
3. Standardize column names and date formats
4. Add 'source' column
5. Concatenate and deduplicate (title + date + city)
6. Save cleaned version as data/cleaned_events.csv

------------------------------------------------------
PHASE 4 — AI-BASED CLASSIFICATION & TAGGING
------------------------------------------------------
Objective: Filter for tech-related events using LLMs or keyword rules.

Tasks:
1. Create src/processing/filter_events.py
2. Use keyword-based filter first (tech, software, AI, startup, coding, developer)
3. Integrate OpenAI or Claude for semantic classification
4. Prompt example:
   “Given this event description, is this event technology-related? (yes/no)”
5. Batch classify all events
6. Save filtered results → filtered_events.csv
7. Add category tags (conference, meetup, workshop)
8. Log results to /logs/classification.log

------------------------------------------------------
PHASE 5 — STORAGE LAYER (DATABASE)
------------------------------------------------------
Objective: Persist all cleaned data for querying.

Tasks:
1. Set up PostgreSQL (local or hosted)
2. Create database: events_db
3. Create table schema (id, title, description, start_time, city, venue, tags, source, url, is_tech)
4. Connect with SQLAlchemy (src/storage/db.py)
5. Write insert_events(df) function
6. Verify insertion with SELECT COUNT(*) FROM events;

------------------------------------------------------
PHASE 6 — QUERY & API LAYER
------------------------------------------------------
Objective: Expose data via an API for easy access.

Tasks:
1. Install FastAPI and Uvicorn
2. Create src/api/app.py
3. Build endpoint:
   GET /events?city=NYC&month=October&category=tech
4. Query DB and return JSON
5. Enable CORS
6. Add pagination and filtering
7. Log API requests to /logs/api.log

------------------------------------------------------
PHASE 7 — FRONTEND / VISUALIZATION LAYER
------------------------------------------------------
Objective: Build a simple UI to view and filter results.

Tasks:
1. Install Streamlit
2. Create src/frontend/app.py
3. Build dropdown filters (city, date, category)
4. Display event cards (title, time, venue, link)
5. Add map visualization (folium / streamlit-folium)
6. Test with streamlit run src/frontend/app.py

------------------------------------------------------
PHASE 8 — AUTOMATION & SCHEDULING
------------------------------------------------------
Objective: Keep data fresh automatically.

Tasks:
1. Write cron or Airflow job to run ingestion daily
2. Example cron: 0 1 * * * python src/ingestion/fetch_all.py
3. Rotate logs weekly
4. Send Slack/email alert on errors
5. Clean up old events (> 60 days)

------------------------------------------------------
PHASE 9 — AI ENHANCEMENTS & FUTURE ADD-ONS
------------------------------------------------------
Objective: Make system more intelligent and scalable.

Tasks:
1. Add natural language query (“Show me AI meetups next week in Brooklyn”)
2. Add personalized recommendations
3. Add LLM-generated event summaries
4. Integrate Google Calendar sync
5. Deploy backend (Render, Vercel, AWS)
6. Deploy Streamlit frontend
7. Document setup for contributors
